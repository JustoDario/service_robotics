Práctica 1: exploración del entorno

Registro del mapa de Gazebo y planificación de una ruta de cobertura con el algoritmo BSA.

En esta memoria

Objetivos · Registro del mapa · Rejilla y exploración · Resultados · Conclusiones

Introducción

El objetivo de la práctica es que un robot aspirador recorra las zonas transitables de un mapa conocido. Para planificar sus movimientos en una rejilla, primero hay que relacionar las coordenadas del mundo de Gazebo con los píxeles de la imagen del mapa. Después, el robot utiliza esa correspondencia para construir una ruta de exploración y seguirla en la simulación.

Objetivos

  • Calcular una transformación entre coordenadas del mundo y coordenadas de píxel a partir de puntos correspondientes.
  • Convertir el mapa en una rejilla y clasificar las celdas transitables y ocupadas.
  • Planificar una ruta de cobertura con BSA, incluyendo el retroceso por celdas ya visitadas cuando sea necesario.
  • Seguir la ruta con el robot simulado y mostrar el resultado.

Desarrollo

Fase 1 · Registro del mapa

La imagen del mapa tiene un tamaño de 1012 × 1012 píxeles. Tomé 15 puntos visibles tanto en Gazebo como en la imagen y anoté para cada uno las coordenadas del mundo (x, y) y las coordenadas de píxel (px, py).

Con esas correspondencias ajusté por mínimos cuadrados una transformación afín homogénea. Si pmundo = [x, y, 1]T, la transformación produce el punto en la imagen: pimagen = T · pmundo.

Cálculo de la matriz en correspondencia.py

import numpy as np

# [x_gazebo, y_gazebo, px_imagen, py_imagen]
datos = [
    [-0.30186, 0.9521, 588.3, 511], [0.1469, 2.85602, 562.4, 715],
    [-1.6915, 2.85536, 752.5, 715], [-2.55, 1.6088, 842.5, 590],
    [-3.7138, -0.8952, 954, 336], [0.9386, 2.0255, 482, 634],
    [2.07344, 2.03278, 380, 634], [2.0402, -3.28678, 372, 90],
    [5.1296, -3.30581, 64, 90], [5.13143, 0.15126, 63, 440],
    [2.7837, 0.5715, 300, 480], [2.783, 4.4345, 295, 861],
    [-2.5, 5.55336, 828, 975], [5.1232, 5.55213, 60, 980],
    [5.1242, 4.8264, 56, 900]
]

P_gazebo = np.array([[fila[0], fila[1], 1] for fila in datos])
P_img = np.array([[fila[2], fila[3]] for fila in datos])

# Ajuste por mínimos cuadrados y paso a coordenadas homogéneas
T_2x3, _, _, _ = np.linalg.lstsq(P_gazebo, P_img, rcond=None)
T_2x3 = T_2x3.T
T = np.vstack([T_2x3, [0, 0, 1]])

np.set_printoptions(suppress=True, precision=3)
print(T)

El ajuste dio la siguiente matriz. Los elementos de la diagonal tienen una magnitud cercana a 100 píxeles por metro; el signo negativo del primer elemento indica que el eje X de Gazebo queda invertido respecto al eje horizontal de la imagen.

T = [[-100.856,   -0.369, 578.571],
     [  -0.492,  100.075, 424.396],
     [   0.000,    0.000,   1.000]]

De la matriz obtuve una escala aproximada de 100,8 píxeles por metro. En el programa guardo la transformación inversa para convertir los centros de las celdas del mapa de vuelta a coordenadas del mundo.

T_inv = np.linalg.inv(T)
scale = 100.8  # píxeles por metro

def world_to_pixel(x, y):
    p_gazebo = np.array([x, y, 1.0])
    p_img = np.dot(T, p_gazebo)
    return int(p_img[0]), int(p_img[1])

Fase 2 · Rejilla y exploración

Dividí el mapa en celdas del tamaño aproximado del robot, cuyo diámetro es 0,34 m. Con la escala calculada, cada celda ocupa int(0,34 × 100,8) = 34 píxeles por lado. Mantengo dos representaciones: gridmap almacena el estado de cada celda para la planificación y display_map sirve para visualizar la rejilla y el recorrido.

Para marcar obstáculos, erosiono la imagen y cuento los píxeles oscuros de cada celda. Si más del 60 % son oscuros, la celda se considera ocupada.

Inicialización de las celdas ocupadas en p1.py

cell_size = int(robot_diameter * scale)
gridmap = np.zeros((grid_rows, grid_cols), dtype=int)

kernel = np.ones((35, 35), np.uint8)
eroded = cv2.erode(gray, kernel, iterations=1)

for r in range(grid_rows):
    for c in range(grid_cols):
        y0, y1 = r * cell_size, (r + 1) * cell_size
        x0, x1 = c * cell_size, (c + 1) * cell_size
        pixels = eroded[y0:y1, x0:x1]
        obstacle_pixels = np.sum(pixels < 128)

        if obstacle_pixels / pixels.size > 0.6:
            gridmap[r, c] = OBSTACLE

El planificador BSA explora primero en el orden norte, este, sur y oeste. Al llegar a un punto sin celdas libres vecinas, vuelve a un punto de retorno y busca un camino por celdas visitadas. El plan completo se guarda en path antes de que empiece el movimiento.

# Prioridad de exploración: norte, este, sur y oeste
next_dir = -2
if is_cell_free(r - 1, c):
    backtracking_stack.append((r, c))
    next_dir = NORTH
elif is_cell_free(r, c + 1):
    backtracking_stack.append((r, c))
    next_dir = EAST
elif is_cell_free(r + 1, c):
    backtracking_stack.append((r, c))
    next_dir = SOUTH
elif is_cell_free(r, c - 1):
    backtracking_stack.append((r, c))
    next_dir = WEST

if next_dir == -2:
    target_r, target_c = -1, -1
    while backtracking_stack:
        pr, pc = backtracking_stack[-1]
        if (is_cell_free(pr - 1, pc) or is_cell_free(pr, pc + 1)
                or is_cell_free(pr + 1, pc) or is_cell_free(pr, pc - 1)):
            target_r, target_c = pr, pc
            break
        backtracking_stack.pop()

    if target_r != -1:
        return_route = bfs_path(r, c, target_r, target_c)

Durante la ejecución, el bucle de control actualiza la pose del robot y, al alcanzar el objetivo actual, extrae el siguiente paso de la ruta. Para avanzar a una celda calculo su centro y lo convierto a coordenadas del mundo mediante la matriz inversa.

Problemas y decisiones

  1. Cuándo planificar la ruta. Al principio intenté recalcular el siguiente movimiento cada vez que el robot llegaba a una celda. Tras revisarlo en clase, cambié a calcular la ruta completa al inicio y seguirla. Así, el planificador mantiene el orden de cobertura y el controlador se ocupa de alcanzar cada objetivo.
  2. Parámetros de la rejilla. Tuve que ajustar la erosión, el porcentaje de píxeles oscuros que define un obstáculo y el tamaño de celda. Fijé la celda al diámetro del robot y ajusté el umbral para obtener una representación útil del mapa.

Conclusiones

La práctica conecta tres partes del problema: registrar el mapa respecto al mundo de Gazebo, discretizar el entorno para representar obstáculos y zonas visitadas, y planificar una ruta que el robot pueda seguir. La matriz afín permitió convertir entre píxeles y metros, y la rejilla hizo posible aplicar la exploración BSA sobre celdas del tamaño del robot.

La experiencia también mostró que separar la planificación de la ruta del control de movimiento facilita organizar el programa. Como siguiente mejora, sería interesante revisar el plan durante la ejecución si aparecieran obstáculos dinámicos.
